State, time, and delay

In the previous lesson, the controller appeared continuous. Now we will turn it into a program that wakes at fixed intervals, reads a sensor, and takes one step.

Lesson outcome. You will be able to identify a model's state, calculate one discrete transition by hand, and explain why infrequent or delayed measurements can destabilize even a simple controller.

1. State is memory of the present

State is the minimal set of variables that, together with future commands, allows a model to predict the future. In our model, the command directly sets velocity, so the only state is position x.

Imagine a real rolling ball. Two balls can occupy the same position while one is stationary and the other is moving quickly. Their futures differ, so position alone is no longer enough: velocity must be added to the state.

Not everything is state. Target r is set externally, command u is computed by the controller, and measurement y communicates something about the state. Sometimes y=x, but delay and noise quickly separate these concepts.

The primary source defines state as a set of variables that summarizes the system's past for predicting its future: Feedback Systems, System Modeling. For a short additional intuition, see What is a state?

2. A derivative becomes a step

The formula dx/dt = u states how quickly position changes. A computer needs an assignment operation. If the command is held for Δt seconds:

xₖ₊₁ = xₖ + Δt · uₖ

Index k is not time in seconds; it is the snapshot number. One complete program cycle is now visible:

yₖ = measured_position()
eₖ = r − yₖ
uₖ = Kₚ · eₖ
xₖ₊₁ = xₖ + Δt · uₖ

4. Why a boundary appears

Without delay, yₖ=xₖ. Substitute the controller into the state transition:

eₖ₊₁ = (1 − KₚΔt) · eₖ

Every step multiplies the error by the same number. This lets us predict the graph before running it:

0 < KₚΔt ≤ 1The error keeps its sign and its magnitude decreases.
1 < KₚΔt < 2The sign alternates and the magnitude decreases.
KₚΔt ≥ 2The error magnitude does not decrease.

A large step means that a command becoming outdated acts longer before the next measurement. With delay, the controller receives an even older yₖ=xₖ₋d; the simple boundary above no longer describes the whole system.

Connection to reality. For our integrator model, the transition is exact while the command is held between measurements. For more complex physics, such a formula will often be only a numerical approximation, and we will need to distinguish the controller frequency from the physics simulator's time step.
