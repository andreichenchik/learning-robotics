A robot as a feedback loop

The first virtual robot will be extremely simple. Yet you will see a structure that remains inside a wheeled robot, a manipulator, and a quadrotor.

Lesson outcome. You will be able to predict the behavior of a proportional controller, tune its gain in a simulation, and explain why a robot must continuously measure the result of its actions.

1. The core idea: action is a loop

A program without feedback says, "apply this command." A feedback controller asks again and again, "where are we relative to the target, and what correction should we apply now?"

This matches the basic sensing → computation → actuation architecture from Chapter 1 of Åström and Murray: a closed loop measures the difference between actual and desired values and creates a corrective action. Primary source: Feedback Systems, Chapter 1.

2. One idea from three perspectives

Intuitively: a spring

Imagine an invisible spring between the robot and the target. The farther the robot is from the target, the harder the spring pulls. At the target, the extension disappears, so the command disappears too.

Formally: error becomes a command

error: e = r − x
command: u = Kₚ · e
motion: dx/dt = u

r is the target position, x is the current position, u is velocity, and Kₚ determines how strongly the controller responds. If the robot is left of the target, the error is positive and the command points right. As the robot approaches, both error and velocity decrease.

Algorithmically: repeat

while robot_is_running:
  error = target - measured_position
  command = gain * error
  send_to_actuator(command)
Model boundary. Our "robot" is a point on a rail that executes velocity commands instantly. It has no mass, wheels, orientation, sensor noise, or delay yet. This deliberately isolates one idea; it is not realistic physics.

3. Experiment

Position x0.140
Error e0.640
Command u0.000

Set the gain and run the loop.

  1. Before running it, predict what happens when Kₚ = 0. Then check.
  2. Compare Kₚ = 0.4 and Kₚ = 2.4. Watch the error and command as well as the robot.
  3. Wait until the robot reaches the target, then select "Push the robot." Why does the command appear sharply and then disappear again?
  4. Move the target while the robot is moving. Find which line of the algorithm immediately receives a new value.
